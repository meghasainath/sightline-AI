Screen readers can't see a video call.

VoiceOver and TalkBack read menus, buttons, and documents. Neither can read a shared slide, a chart, or a presenter's screen during Zoom, Teams, or Google Meet — because that's just pixels, not accessible text. Sightline AI closes that gap.

Where the gap actually is

Every screen reader already does the first half of accessibility well. The second half — live, pixel-only content during a call — has no existing hook.

What works today

Static screens, read fine

VoiceOver and TalkBack narrate accessibility-tree content: labeled buttons, documents, most app UI.

What doesn't

Live call content, invisible

A shared slide or chart rendered inside Zoom, Meet, or Teams is just pixels in a video stream — no accessibility tree to read.

Who told us this

A real pain point, not a guess

This came directly from a visually impaired former colleague describing what actually blocks him at work.

How it works

On‑demand, not proactive — the user presses a key when they want to know what changed, so the AI never talks over whoever is presenting.

Design decisions

Choices made deliberately for this user base, not defaults.

On‑demand, never proactive

The user controls when a description happens, so it can't interrupt someone speaking.

Visual‑only descriptions

Never repeats what's being said aloud — the user can already hear that. Only describes what's silently on screen.

Speech that can't be cut off

The app waits for a description to finish speaking before accepting the next request.

Model fallback, not a single point of failure

Tries several Gemini model names in order, so one overloaded or deprecated model doesn't take the whole tool down.

Privacy over raw accuracy

On‑device processing is the long‑term goal — a real trust differentiator for a user base sharing work calls, even if it costs some sharpness versus a cloud model.

Roadmap

What exists today, and what comes after the idea is validated.

  • One‑shot screenshot → Gemini → spoken description (macOS)
  • Validate description quality with real users
  • Target the active call window instead of full screen
  • Global hotkey instead of a terminal prompt
  • Continuous capture with frame‑differential filtering
  • On‑device processing for privacy
  • Windows support
  • Mobile — Android (MediaProjection/AccessibilityService), iOS (ReplayKit)

Built for the people existing tools describe only in theory: visually impaired professionals in live work calls, and senior users who've never touched a screen reader at all.
